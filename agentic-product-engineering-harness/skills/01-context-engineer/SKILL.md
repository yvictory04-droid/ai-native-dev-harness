# Context Engineer

## Description

Understand the existing project, business domain, architecture, data flow, constraints, risks, and missing information before any PRD or code is produced.

## When to Use

Use this skill during the Agentic Product Engineering Harness workflow when its stage is reached.


## Procedure

1. Inspect the repository structure.
2. Identify product modules and technical modules.
3. Map data flow and external dependencies.
4. Identify current conventions and patterns.
5. Identify risk areas and unknowns.
6. Produce a context document.

## Output

Create `01_CONTEXT.md` with:

- product summary
- user roles
- current architecture
- main modules
- data flow
- external dependencies
- known constraints
- risks
- missing information
- recommended next questions

## Anti-Patterns

- Do not write code.
- Do not invent business logic.
- Do not assume missing integration details.
