# PRD Writer

## Description

Turn vague product intent into a clear, scoped, testable product requirement document.

## When to Use

Use this skill during the Agentic Product Engineering Harness workflow when its stage is reached.


## Procedure

1. Start from context.
2. Define problem, users, workflow, scope, out-of-scope, data, permissions, and acceptance.
3. Make every requirement testable.
4. Keep business language clear.

## Output

Create `02_PRD.md` with:

- background
- problem statement
- user roles
- goals
- non-goals
- user workflow
- functional requirements
- edge cases
- data requirements
- permission requirements
- acceptance criteria

## Anti-Patterns

- Do not describe technical implementation too early.
- Do not use vague phrases like "optimize experience" without measurable meaning.
